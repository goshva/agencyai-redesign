# Компонентная карта AgencyAI

## Принцип

Эталонные страницы остаются обычными HTML-документами без React/Vue и без сборочных runtime-зависимостей. Повторяемые блоки размечены собственными HTML-элементами (`ui-*`) и оформляются общей CSS-системой. Компоненты используют Light DOM: содержимое доступно браузеру, поиску, тестам и assistive technology; стили не скрыты в Shadow DOM.

`components.js` отвечает только за базовую семантику и предсказуемое отображение компонентов. Вся демонстрационная интерактивность остаётся в `reference.js`. Никакой компонент эталона не должен напрямую обращаться к `src/core`.

## Общие компоненты

| Компонент | HTML-тег | Назначение | Где используется |
|---|---|---|---|
| Sidebar | `ui-sidebar` | Бренд, основная навигация, нижняя зона | Все 7 экранов |
| Topbar | `ui-topbar` | Контекст страницы, поиск, действия | Все 7 экранов |
| KPI Card | `ui-kpi` | Ключевой показатель с подписью и статусом | Обзор |
| Panel | `ui-panel` | Универсальная карточка/секция | Все экраны |
| Status Badge | `ui-badge` | Приоритет, статус процесса, роль | Список, карточка, модель |
| SLA Badge | `ui-sla` | Состояние и остаток SLA | Обзор, список, карточка |
| Activity Item | `ui-activity` | Запись ленты событий | Обзор, карточка, хронология |
| Chat Message | `ui-chat-message` | Одно сообщение в read-only переписке | Переписка |
| Process Node | `ui-process-node` | Узел схемы процесса | Модель процесса |

## Компоненты следующего уровня реализации

Эти блоки пока описаны как композиционные паттерны и должны выделяться в отдельные компоненты на соответствующих этапах, когда будет подтверждён контракт данных:

- `FilterBar` — поиск, фильтры и сброс.
- `DataTable` — таблица с сортировкой, пустым состоянием и адаптивным представлением.
- `IncidentSummary` — краткая карточка обращения.
- `IncidentHeader` — номер, заголовок, приоритет, текущий статус.
- `SlaSummary` — состояние SLA и основание вычисления.
- `TimelineToolbar` — выбор даты, режима и масштаба.
- `GitGraph` — визуализация ветвей/событий.
- `GanttChart` — шкала времени и интервалы узлов.
- `ChatThread` — группировка сообщений по роли/времени.
- `ProcessCanvas` — размещение узлов и связей.
- `EmptyState`, `ReadOnlyNotice`, `DemoNotice` — общие состояния и предупреждения.

Не создавать абстрактный компонент ради одного текстового блока. Компонент должен иметь повторное применение, самостоятельный визуальный контракт или отдельный тестируемый сценарий.

## Контракт компонентов

1. Компонент получает отображаемые данные через параметры/свойства или готовую разметку.
2. Компонент не вычисляет SLA, права, переходы и состояние модели.
3. Статус всегда передаётся из существующего селектора `src/core`.
4. Цвет статуса дублируется текстовой меткой и/или иконкой.
5. Интерактивный элемент имеет доступное имя, клавиатурное управление и видимый focus.
6. Отсутствующее поле не заменяется выдуманным значением: скрыть его или показать «Нет данных».
7. В референсах демонстрационные данные явно помечены как условные.

## Изменение эталонных HTML

На страницах применены custom tags с сохранением исходных CSS-классов. Например:

```html
<ui-kpi class="kpi danger">
  <div class="kpi-top">...</div>
  <div class="kpi-value">12</div>
</ui-kpi>

<ui-panel class="panel">
  <div class="panel-head">...</div>
  ...
</ui-panel>

<ui-badge class="badge red">Просрочено</ui-badge>
<ui-sla class="sla amber">Осталось 3 ч</ui-sla>
```

Стили визуального эталона остаются централизованными в `assets/reference.css` и `assets/components.css`.

## Definition of Done компонента

- один компонент имеет один ясный визуальный контракт;
- размеры и состояния согласованы с design tokens;
- не ломает соседние экраны и responsive layout;
- доступен с клавиатуры, если интерактивен;
- имеет минимум один позитивный и один edge-case сценарий;
- нет зависимости от условных данных HTML-эталона;
- тестируется изолированно и в составе экрана.
